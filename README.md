# inverted-index.py

Инвертированный индекс для страниц сайта с дельта-кодированием и гамма-кодом Элиаса. 

## Установка

```bash
git clone https://github.com/mikhaylovilya/inverted-index.py.git
cd inverted-index.py
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
```

## Подготовка данных
Исходный файл краулера ожидается из web-crawler.py. 

```bash
python -m inverted_index convert \
  pages.json \
  data/pages.jsonl
```

Команда берёт массив `pages` из JSON и записывает по одной странице на строку JSONL, добавляя последовательный `id`. Остальные поля страницы сохраняются.

## Построение индекса

```bash
python -m inverted_index build data/pages.jsonl data/index.pkl
```

Индекс строится по заголовку и очищенному тексту страницы. Токенизация приводит текст к нижнему регистру, выделяет буквенно-цифровые последовательности и заменяет `ё` на `е`. Для каждого термина хранятся идентификаторы документов, сжатые дельта- и гамма-кодом.

Пример вывода:

```json
{
  "documents": 100,
  "terms": 14365,
  "postings": 67183,
  "compressed_bytes": 43186,
  "classic_bytes": 268732,
  "compression_ratio": 0.16070285637735737,
  "saved_percent": 83.92971436226426
}
```

## Поиск

```bash
python -m inverted_index search \
  "Ректор СПбГУ/МГУ" \
  --index data/index.pkl \
  --documents data/pages.jsonl \
  --limit 10
```

По умолчанию используется OR-поиск: документы ранжируются по числу найденных терминов. Для AND-поиска добавьте `--all`. Флаг `--json` выводит результат в JSON вместе со временем поиска.

```bash
python -m inverted_index search \
  "Ректор СПбГУ/МГУ" \
  --index data/index.pkl \
  --documents data/pages.jsonl \
  --json
```

## Бенчмарк

```bash
python -m inverted_index benchmark \
  data/pages.jsonl \
  --query "Ректор СПбГУ/МГУ" \
  --target-docs 40000 \
  --repeats 10 \
  --output data/benchmark-40000.json
```

Бенчмарк измеряет:

- время сбора несжатых posting-списков;
- время дельта- и гамма-кодирования;
- общую скорость индексирования;
- размер posting-списков в классическом виде и после сжатия;
- медианное время OR-поиска по сжатому и классическому индексу.

Если в исходном JSONL меньше `--target-docs` документов, корпус циклически повторяется до нужного размера. Это позволяет прогнать сценарий на 40 000 документов, когда реальных страниц меньше. `--target-docs 0` отключает масштабирование.

## Результаты измерений

Измерения выполнены на 100 реальных страницах СПбГУ и на корпусе из 40 000 документов, полученном циклическим повторением этих страниц. Время зависит от машины и состава корпуса.

### 100 реальных страниц

| Показатель | Значение |
| --- | --- |
| Документов | 100 |
| Терминов | 14 365 |
| Posting-записей | 67 183 |
| Классический размер, 4 байта на запись | 268 732 Б |
| Сжатый размер | 43 186 Б |
| Доля от классического | 16,07% |
| Экономия | 83,93% |
| Сбор posting-списков | 0,0587 с |
| Сжатие | 0,0185 с |
| Всего индексирование | 0,0772 с |
| Скорость индексирования | 1 296 документов/с |
| Поиск, сжатый индекс | 0,0465 мс |
| Поиск, классический индекс | 0,0133 мс |
| Найдено документов | 100 |

### 40 000 документов

| Показатель | Значение |
| --- | --- |
| Документов | 40 000, из них 39 900 синтетических |
| Терминов | 14 365 |
| Posting-записей | 26 873 200 |
| Классический размер, 4 байта на запись | 107 492 800 Б |
| Сжатый размер | 16 189 718 Б |
| Доля от классического | 15,06% |
| Экономия | 84,94% |
| Сбор posting-списков | 23,23 с |
| Сжатие | 4,40 с |
| Всего индексирование | 27,63 с |
| Скорость индексирования | 1 447,82 документов/с |
| Скорость без сжатия | 1 721,96 документов/с |
| Поиск, сжатый индекс | 19,70 мс |
| Поиск, классический индекс | 5,78 мс |
| Найдено документов | 40 000 |

Сжатие уменьшает объём posting-списков примерно в 6,2–6,6 раза. Поиск по сжатому индексу медленнее, потому что перед ранжированием posting-списки нужно распаковать. Экономия достигается за счёт хранения: 15–16% от классического размера.

Запрос `Ректор СПбГУ/МГУ` в OR-режиме находит все документы, где встречается хотя бы один из терминов; в корпусе СПбГУ общие термины встречаются очень часто, поэтому результат близок ко всему корпусу. Время поиска указано для такого полного результата.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты проверяют:

- токенизацию;
- гамма-код и дельта-кодирование, включая точный битовый layout;
- преобразование JSON в JSONL;
- сбор posting-списков;
- дедупликацию документов по термину;
- OR- и AND-поиск;
- сохранение и загрузку индекса;
- бенчмарк и циклическое масштабирование корпуса;
- команды CLI.

## Структура

```text
inverted_index/
  coding.py      дельта- и гамма-кодирование posting-списков
  corpus.py      JSON -> JSONL и чтение документов
  tokenizer.py   токенизация русского и английского текста
  index.py       построение, поиск и сохранение индекса
  benchmark.py   замеры индексирования, сжатия и поиска
  cli.py         команды convert, build, search, benchmark
tests/           pytest-тесты
```
